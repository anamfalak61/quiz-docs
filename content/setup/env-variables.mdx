# Environment Variables

Settings and secret keys should never be written directly in your code. Store them in a `.env.local` file instead.

## Create `.env.local`

In the project root (next to `package.json`), create this file:

```bash filename=".env.local"
NEXT_PUBLIC_TRIVIA_API_URL=https://opentdb.com/api.php
```

The Open Trivia DB API does not need an API key, so this file only holds the base URL. If an API does require a key, store it like this:

```bash filename=".env.local"
# No NEXT_PUBLIC_ prefix, so this is only available on the server (safe)
SECRET_API_KEY=your_key_here
```

## Use it in code

```ts filename="lib/api.ts"
const BASE_URL = process.env.NEXT_PUBLIC_TRIVIA_API_URL

if (!BASE_URL) {
  throw new Error('NEXT_PUBLIC_TRIVIA_API_URL is not set in .env.local')
}
```

## What `NEXT_PUBLIC_` means

| Name | Where it is visible |
| --- | --- |
| `NEXT_PUBLIC_API_URL` | In the browser too (anyone can see it) |
| `SECRET_API_KEY` | Server only (safe) |

<Callout type="warning">
  Never add the `NEXT_PUBLIC_` prefix to a secret key. It would be bundled into the browser code and anyone could read it.
</Callout>

## Keep it out of Git

The `.gitignore` created by `create-next-app` already ignores `.env*` files, but double-check it. Commit a `.env.example` file instead, with the variable names and no values:

```bash filename=".env.example"
NEXT_PUBLIC_TRIVIA_API_URL=
SECRET_API_KEY=
```

<Callout type="info">
  After changing `.env.local`, stop the dev server and run `npm run dev` again. Otherwise the new value will not load.
</Callout>
