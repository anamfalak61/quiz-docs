# TypeScript Setup

We use **strict mode** so that mistakes are caught before the app runs.

## Create the project

```bash
npx create-next-app@latest weather-dashboard --typescript --tailwind --app --eslint --no-src-dir --import-alias "@/*"
cd weather-dashboard
```

This sets up TypeScript, Tailwind CSS and the App Router for you.

## Check strict mode

Open `tsconfig.json` and make sure `strict` is `true`:

```json filename="tsconfig.json"
{
  "compilerOptions": {
    "target": "ES2017",
    "strict": true,
    "noUncheckedIndexedAccess": true,
    "paths": {
      "@/*": ["./*"]
    }
  }
}
```

- `strict: true` turns on all important type checks.
- `noUncheckedIndexedAccess` forces you to handle `undefined` when reading from arrays, such as `weather[0]`.
- `@/*` is an import alias, so you can write `import type { WeatherData } from '@/lib/types'`.

## Write the types first

Describe the shape of the API responses before writing any other code. Create `lib/types.ts`:

```ts filename="lib/types.ts"
export interface WeatherCondition {
  id: number
  main: string
  description: string
  icon: string
}

export interface WeatherData {
  name: string
  coord: {
    lat: number
    lon: number
  }
  timezone: number
  sys: {
    country: string
    sunrise: number
    sunset: number
  }
  main: {
    temp: number
    feels_like: number
    temp_min: number
    temp_max: number
    humidity: number
    pressure: number
  }
  weather: WeatherCondition[]
  wind: {
    speed: number
  }
}

export interface ForecastItem {
  dt: number
  main: {
    temp: number
  }
  weather: WeatherCondition[]
  pop: number
}

export interface ForecastData {
  list: ForecastItem[]
}

export interface DashboardData {
  current: WeatherData
  forecast: ForecastItem[]
}

export interface RecentCity {
  name: string
  country: string
  temp: number
  icon: string
  description: string
}

export interface ApiErrorBody {
  cod: number | string
  message: string
}

export type SearchStatus = 'idle' | 'loading' | 'error' | 'success'
```

What each type is for:

| Type | Used for |
| --- | --- |
| `WeatherData` | The current weather of one city |
| `ForecastItem` | One forecast step, every 3 hours. `pop` is the chance of rain from 0 to 1 |
| `DashboardData` | What your own route returns: current weather and the forecast together |
| `RecentCity` | A saved search, kept in the browser |
| `ApiErrorBody` | The body of an error response |
| `SearchStatus` | Which screen the dashboard shows |

Only the fields the dashboard uses are listed. The API returns more, and TypeScript simply ignores the rest.

<Callout type="info">
  `ApiErrorBody.cod` is typed as `number | string` because the API is not consistent: some error responses send the code as a number and others as a string.
</Callout>

<Callout type="warning">
  Avoid the `any` type. If the API response does not fit a type, fix the type instead of hiding the problem with `any`.
</Callout>
