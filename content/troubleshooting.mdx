# Troubleshooting

Common errors and how to fix them.

## Status codes

| Status | Comes from | Meaning | Fix |
| --- | --- | --- | --- |
| `400` | Your route | No city was sent | Type a city name before searching |
| `401` | Weather API | The API key was rejected | See [401 Invalid API key](#401-invalid-api-key) |
| `404` | Weather API | City not found | See [404 City not found](#404-city-not-found) |
| `429` | Weather API | Too many requests | Wait a moment and try again. Do not retry in a loop |
| `500` | Your route | `OPENWEATHER_API_KEY` is missing | Check `.env.local` and restart the server |
| `502` | Your route | The weather service could not be reached | Check your internet connection and try again |

## 401 Invalid API key

A rejected key returns a response like this:

```json
{
  "cod": 401,
  "message": "Invalid API key. Please see https://openweathermap.org/faq#error401 for more info."
}
```

Check these in order:

1. **The key is brand new.** A new key can need anywhere from a few minutes to a couple of hours before it works. Wait and try again.
2. **A typo in the key.** Copy it again from your API keys page. Make sure there are no spaces or quotes around it in `.env.local`.
3. **You did not restart the server.** Changes to `.env.local` are only loaded when `npm run dev` starts.

<Callout type="info">
  A quick way to test a key outside your app: open `https://api.openweathermap.org/data/2.5/weather?q=Lahore&appid=YOUR_KEY&units=metric` in the browser, with your key in place of `YOUR_KEY`. Never share that address with the key in it.
</Callout>

## 404 City not found

```json
{
  "cod": "404",
  "message": "city not found"
}
```

Notice that `cod` is a string here and a number in the 401 example. That is why `ApiErrorBody.cod` is typed as `number | string`.

- Check the spelling.
- Use the English name of the city.
- To avoid mix-ups between cities with the same name, add the country code: `Lahore,PK`.

<Callout type="warning">
  `fetch` only throws on network failures. It does **not** throw on 401 or 404, so always check `response.ok` before reading the body.
</Callout>

## Common problems

### "The server is missing OPENWEATHER_API_KEY"

`.env.local` is missing, is in the wrong folder, or the variable name is misspelled. The file must sit next to `package.json` and contain exactly `OPENWEATHER_API_KEY=your_key`. Restart the dev server afterwards.

### It works locally but fails after deploying

`.env.local` is not uploaded to your host, on purpose. Add `OPENWEATHER_API_KEY` in your hosting dashboard under environment variables, then deploy again so the new value is used.

### The weather icon does not appear

If you use `next/image`, the icon host must be allowed in `next.config.ts` under `images.remotePatterns`. See [UI & Styling](/guides/ui-styling). Restart the dev server after editing that file.

### Hydration error about `localStorage`

Do not read `localStorage` while rendering. Read it inside `useEffect`, as the dashboard page does, so the server and the browser render the same HTML first.

### Tailwind classes have no effect

Tailwind does not detect dynamic class names such as `` `bg-${color}-500` ``. Write the full class name, or map values to complete strings.

### `Cannot find module '@/lib/...'`

The import alias is missing. Check that `tsconfig.json` has `"paths": { "@/*": ["./*"] }`, then restart the TypeScript server in your editor.

### Port 3000 is already in use

Another process is running. Stop it, or start on another port:

```bash
npm run dev -- -p 3001
```

## Still stuck?

Open the browser DevTools (**F12**), go to the **Network** tab, and click the failing request. The status code and the response body usually tell you what went wrong. Your API key should never appear in the request address. If it does, the key is exposed and you should generate a new one.
