# Implementation

In this guide we connect the Weather Dashboard to the weather API. You will build a **server route** that keeps your API key secret, a typed fetch function, loading and error states, city search, and a recent searches history. At the end you put all the components together on one page.

<Callout type="info">
  Complete [Setup](/setup/folder-structure) and [UI & Styling](/guides/ui-styling) first. This guide uses the types from Setup, the components from UI & Styling, and the key in your `.env.local`.
</Callout>

## How the data flows

```text
Browser  →  /api/dashboard?city=Lahore  →  Weather API (current weather)
            (your server route)          →  Weather API (forecast)
                                            (key added on the server)
```

The browser never sees the API key. It only talks to your own route, and the route adds the key on the server.

## 1. Build the server route

Create `app/api/dashboard/route.ts`. It makes two requests and returns both results together:

1. **Current weather** for the city name. The response contains the city's coordinates.
2. **Forecast** for those coordinates. The forecast request needs a latitude and a longitude, which is why it has to come second.

```ts filename="app/api/dashboard/route.ts"
import { NextResponse } from 'next/server'
import type { ApiErrorBody, DashboardData, ForecastData, WeatherData } from '@/lib/types'

const BASE_URL = 'https://api.openweathermap.org/data/2.5'

function errorBody(status: number, message: string) {
  return NextResponse.json({ cod: status, message }, { status })
}

export async function GET(request: Request) {
  const apiKey = process.env.OPENWEATHER_API_KEY

  if (!apiKey) {
    return errorBody(500, 'The server is missing OPENWEATHER_API_KEY.')
  }

  const city = new URL(request.url).searchParams.get('city')?.trim()

  if (!city) {
    return errorBody(400, 'City is required.')
  }

  let currentResponse: Response
  try {
    currentResponse = await fetch(
      `${BASE_URL}/weather?q=${encodeURIComponent(city)}&appid=${apiKey}&units=metric`,
      { cache: 'no-store' },
    )
  } catch {
    return errorBody(502, 'Could not reach the weather service.')
  }

  if (!currentResponse.ok) {
    const error: ApiErrorBody = await currentResponse.json()
    return NextResponse.json(error, { status: currentResponse.status })
  }

  const current: WeatherData = await currentResponse.json()
  const { lat, lon } = current.coord

  let forecastResponse: Response
  try {
    forecastResponse = await fetch(
      `${BASE_URL}/forecast?lat=${lat}&lon=${lon}&appid=${apiKey}&units=metric`,
      { cache: 'no-store' },
    )
  } catch {
    return errorBody(502, 'Could not reach the weather service.')
  }

  if (!forecastResponse.ok) {
    const error: ApiErrorBody = await forecastResponse.json()
    return NextResponse.json(error, { status: forecastResponse.status })
  }

  const forecast: ForecastData = await forecastResponse.json()
  const body: DashboardData = { current, forecast: forecast.list }

  return NextResponse.json(body)
}
```

What this route does:

- Reads the key from `process.env`. This only works on the server.
- Rejects an empty city with `400` before calling the API.
- `encodeURIComponent` makes names like `New York` safe to put in a URL.
- `units=metric` asks for Celsius. The °F switch converts in the browser, so no second request is needed.
- It passes the API's own status code through, so a `401` or `404` from the weather API reaches your UI unchanged.
- `cache: 'no-store'` makes sure you always get fresh weather.

### Test the route

Start the app and open this address in the browser:

```text
http://localhost:3000/api/dashboard?city=Lahore
```

You should see JSON with two parts: `current` (an object) and `forecast` (a long list). Now open DevTools (**F12**), go to the **Network** tab and click the request. The request URL contains your own address only, with **no `appid`**. That is the proof that the key stays on the server.

<Callout type="warning">
  Never put the API key in a file inside `components/` or in a page marked `'use client'`. Anything there is sent to the browser.
</Callout>

## 2. Fetch from the browser

Create `lib/weather.ts`. It calls your route and turns every failure into a readable message.

```ts filename="lib/weather.ts"
import type { DashboardData } from '@/lib/types'

export class WeatherApiError extends Error {
  status: number

  constructor(message: string, status: number) {
    super(message)
    this.name = 'WeatherApiError'
    this.status = status
  }
}

export function messageForStatus(status: number): string {
  switch (status) {
    case 400:
      return 'Please enter a city name.'
    case 401:
      return 'The weather service rejected the API key. Check OPENWEATHER_API_KEY and restart the server.'
    case 404:
      return 'City not found. Check the spelling and try again.'
    case 429:
      return 'Too many requests. Please wait a moment and try again.'
    default:
      return status >= 500
        ? 'The weather service is having problems. Please try again later.'
        : `Request failed with status ${status}.`
  }
}

export async function fetchDashboard(city: string): Promise<DashboardData> {
  let response: Response

  try {
    response = await fetch(`/api/dashboard?city=${encodeURIComponent(city)}`)
  } catch {
    throw new WeatherApiError('Network error. Please check your internet connection.', 0)
  }

  if (!response.ok) {
    throw new WeatherApiError(messageForStatus(response.status), response.status)
  }

  return (await response.json()) as DashboardData
}
```

<Callout type="warning">
  `fetch` only throws on network failures. It does **not** throw on 401 or 404, so always check `response.ok` before reading the body.
</Callout>

<Callout type="info">
  `as DashboardData` tells TypeScript to trust the shape of the response. It is not a runtime check. That is acceptable here because the data comes from your own route.
</Callout>

### The same call with axios

If you prefer `axios` (`npm install axios`), it throws automatically for 4xx and 5xx statuses:

```ts filename="lib/weather.axios.ts"
import axios, { AxiosError } from 'axios'
import { WeatherApiError, messageForStatus } from '@/lib/weather'
import type { DashboardData } from '@/lib/types'

export async function fetchDashboardWithAxios(city: string): Promise<DashboardData> {
  try {
    const { data } = await axios.get<DashboardData>('/api/dashboard', { params: { city } })
    return data
  } catch (error) {
    if (error instanceof AxiosError && error.response) {
      throw new WeatherApiError(messageForStatus(error.response.status), error.response.status)
    }
    throw new WeatherApiError('Network error. Please check your internet connection.', 0)
  }
}
```

## 3. Save recent searches

We store the last six searches in the browser with `localStorage`. Each entry keeps the city name, country, temperature, icon and description, which is what the **Other Cities** cards need.

```ts filename="lib/history.ts"
import type { RecentCity } from '@/lib/types'

const KEY = 'recent-cities-v2'
const MAX_ENTRIES = 6

export function loadHistory(): RecentCity[] {
  if (typeof window === 'undefined') return []

  try {
    const raw = window.localStorage.getItem(KEY)
    return raw ? (JSON.parse(raw) as RecentCity[]) : []
  } catch {
    return []
  }
}

export function addCity(city: RecentCity): RecentCity[] {
  const updated = [
    city,
    ...loadHistory().filter((item) => item.name.toLowerCase() !== city.name.toLowerCase()),
  ].slice(0, MAX_ENTRIES)

  try {
    window.localStorage.setItem(KEY, JSON.stringify(updated))
  } catch {
    // Storage can be full or blocked. The dashboard still works without history.
  }

  return updated
}
```

`addCity` removes an older copy of the same city first, so a city never appears twice, and the newest search is always first.

<Callout type="info">
  `localStorage` does not exist on the server, which is why `loadHistory` checks `typeof window`. We also read it inside `useEffect` in the next step, so the server and the browser render the same HTML first.
</Callout>

<Callout type="info">
  The storage key ends in `-v2`. If you change the shape of the saved data later, change the key too, so old saved data in a visitor's browser is ignored instead of breaking the page.
</Callout>

## 4. Build the dashboard page

The page is a small state machine driven by `status`: idle, loading, error and success. It also holds the temperature unit and the saved searches, and passes them down to the components.

```tsx filename="app/page.tsx"
'use client'

import { useEffect, useState } from 'react'
import CurrentWeather from '@/components/CurrentWeather'
import ForecastPanel from '@/components/ForecastPanel'
import Highlights from '@/components/Highlights'
import OtherCities from '@/components/OtherCities'
import SearchBar from '@/components/SearchBar'
import type { Unit } from '@/lib/format'
import { addCity, loadHistory } from '@/lib/history'
import type { DashboardData, RecentCity, SearchStatus } from '@/lib/types'
import { fetchDashboard, WeatherApiError } from '@/lib/weather'

export default function Home() {
  const [status, setStatus] = useState<SearchStatus>('idle')
  const [data, setData] = useState<DashboardData | null>(null)
  const [unit, setUnit] = useState<Unit>('C')
  const [errorMessage, setErrorMessage] = useState('')
  const [history, setHistory] = useState<RecentCity[]>([])

  useEffect(() => {
    setHistory(loadHistory())
  }, [])

  async function search(city: string) {
    setStatus('loading')
    setErrorMessage('')

    try {
      const result = await fetchDashboard(city)
      const condition = result.current.weather[0]

      setData(result)
      setHistory(
        addCity({
          name: result.current.name,
          country: result.current.sys.country,
          temp: result.current.main.temp,
          icon: condition?.icon ?? '01d',
          description: condition?.description ?? '',
        }),
      )
      setStatus('success')
    } catch (error) {
      setErrorMessage(
        error instanceof WeatherApiError
          ? error.message
          : 'Something went wrong. Please try again.',
      )
      setStatus('error')
    }
  }

  return (
    <div>
      <header className="mb-6 flex flex-col gap-4 sm:flex-row sm:items-center sm:justify-between">
        <h1 className="text-3xl font-extrabold tracking-tight">
          Weather <span className="text-emerald-400">Dashboard</span>
        </h1>
        <div className="w-full sm:max-w-md">
          <SearchBar onSearch={search} disabled={status === 'loading'} />
        </div>
      </header>

      <div className="mt-8">
        {status === 'idle' && (
          <div className="rounded-3xl border-2 border-dashed border-emerald-400/30 bg-emerald-900/20 p-10 text-center">
            <p aria-hidden="true" className="text-4xl">
              ⛅
            </p>
            <p className="mt-3 text-emerald-100/80">Search for a city to see its weather.</p>
          </div>
        )}

        {status === 'loading' && (
          <div
            role="status"
            aria-label="Loading weather"
            className="animate-pulse rounded-3xl bg-emerald-900/40 p-8"
          >
            <div className="h-4 w-1/4 rounded-full bg-emerald-800/70" />
            <div className="mt-8 h-24 w-1/2 rounded-2xl bg-emerald-800/70" />
            <div className="mt-6 h-4 w-1/3 rounded-full bg-emerald-800/70" />
          </div>
        )}

        {status === 'error' && (
          <div
            role="alert"
            className="rounded-2xl border border-red-400/30 bg-red-500/10 p-4 text-center font-medium text-red-200"
          >
            {errorMessage}
          </div>
        )}

        {status === 'success' && data && (
          <div className="grid gap-6 lg:grid-cols-5">
            <div className="space-y-6 lg:col-span-3">
              <CurrentWeather
                current={data.current}
                forecast={data.forecast}
                unit={unit}
                onUnitChange={setUnit}
              />
              <ForecastPanel current={data.current} forecast={data.forecast} unit={unit} />
            </div>
            <div className="space-y-6 lg:col-span-2">
              <Highlights current={data.current} forecast={data.forecast} />
              <OtherCities
                cities={history}
                activeName={data.current.name}
                unit={unit}
                onSelect={search}
              />
            </div>
          </div>
        )}

        {status !== 'success' && (
          <div className="mt-8">
            <OtherCities cities={history} activeName="" unit={unit} onSelect={search} />
          </div>
        )}
      </div>
    </div>
  )
}
```

### How the pieces work together

<Steps>

### The user searches

`SearchBar` calls `search(city)`. The page sets `status` to `loading`, which also disables the button so the user cannot send the request twice.

### The request finishes

On success we store the result, save a snapshot of the city in the history, and move to `success`. On failure the `catch` block saves a readable message and moves to `error`.

### The user switches units or picks another city

The `unit` state lives in the page, so one click on **°F** updates every card. Clicking a card in **Other Cities** calls the same `search` function, so there is only one code path to maintain.

</Steps>

<Callout type="warning">
  Always keep the **loading** and **error** states. Without them, a slow network shows nothing, and a failed request leaves the user with no explanation.
</Callout>
