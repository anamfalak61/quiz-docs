# Implementation

In this guide we connect the Weather Dashboard to the weather API. You will build a **server route** that keeps your API key secret, a typed fetch function, loading and error states, city search, and a recent searches history.

<Callout type="info">
  Complete [Setup](/setup/folder-structure) and [UI & Styling](/guides/ui-styling) first. This guide uses the `SearchBar`, `WeatherCard` and `RecentSearches` components from there, and the key from your `.env.local`.
</Callout>

## How the data flows

```text
Browser  →  /api/weather?city=Lahore  →  Weather API
            (your server route)           (key added here)
```

The browser never sees the API key. It only talks to your own route, and the route adds the key on the server.

## 1. Add one more type

Add this to the end of `lib/types.ts`:

```ts filename="lib/types.ts"
export type SearchStatus = 'idle' | 'loading' | 'error' | 'success'
```

`SearchStatus` lists every screen the dashboard can be in. Because it is a union type, TypeScript warns you if you forget to handle one of them.

## 2. Build the server route

Create `app/api/weather/route.ts`:

```ts filename="app/api/weather/route.ts"
import { NextResponse } from 'next/server'
import type { ApiErrorBody, WeatherData } from '@/lib/types'

const BASE_URL = 'https://api.openweathermap.org/data/2.5/weather'

export async function GET(request: Request) {
  const apiKey = process.env.OPENWEATHER_API_KEY

  if (!apiKey) {
    return NextResponse.json(
      { cod: 500, message: 'The server is missing OPENWEATHER_API_KEY.' },
      { status: 500 },
    )
  }

  const city = new URL(request.url).searchParams.get('city')?.trim()

  if (!city) {
    return NextResponse.json({ cod: 400, message: 'City is required.' }, { status: 400 })
  }

  const url = `${BASE_URL}?q=${encodeURIComponent(city)}&appid=${apiKey}&units=metric`

  let response: Response
  try {
    response = await fetch(url, { cache: 'no-store' })
  } catch {
    return NextResponse.json(
      { cod: 502, message: 'Could not reach the weather service.' },
      { status: 502 },
    )
  }

  const body: WeatherData | ApiErrorBody = await response.json()
  return NextResponse.json(body, { status: response.status })
}
```

What this route does:

- Reads the key from `process.env`. This only works on the server.
- Rejects an empty city with `400` before calling the API.
- `encodeURIComponent` makes names like `New York` safe to put in a URL.
- It passes the API's status code through, so a `401` or `404` from the weather API reaches your UI unchanged.

### Test the route

Start the app and open this address in the browser:

```text
http://localhost:3000/api/weather?city=Lahore
```

You should see the weather JSON. Now open DevTools (**F12**), go to the **Network** tab and click the request. The request URL contains your own address only, with **no `appid`**. That is the proof that the key stays on the server.

<Callout type="warning">
  Never put the API key in a file inside `components/` or in a page marked `'use client'`. Anything there is sent to the browser.
</Callout>

## 3. Fetch from the browser

Create `lib/weather.ts`. It calls your route and turns every failure into a readable message.

```ts filename="lib/weather.ts"
import type { WeatherData } from '@/lib/types'

export class WeatherApiError extends Error {
  status: number

  constructor(message: string, status: number) {
    super(message)
    this.name = 'WeatherApiError'
    this.status = status
  }
}

export function messageForStatus(status: number): string {
  switch (status) {
    case 400:
      return 'Please enter a city name.'
    case 401:
      return 'The weather service rejected the API key. Check OPENWEATHER_API_KEY and restart the server.'
    case 404:
      return 'City not found. Check the spelling and try again.'
    case 429:
      return 'Too many requests. Please wait a moment and try again.'
    default:
      return status >= 500
        ? 'The weather service is having problems. Please try again later.'
        : `Request failed with status ${status}.`
  }
}

export async function fetchWeather(city: string): Promise<WeatherData> {
  let response: Response

  try {
    response = await fetch(`/api/weather?city=${encodeURIComponent(city)}`)
  } catch {
    throw new WeatherApiError('Network error. Please check your internet connection.', 0)
  }

  if (!response.ok) {
    throw new WeatherApiError(messageForStatus(response.status), response.status)
  }

  return (await response.json()) as WeatherData
}
```

<Callout type="warning">
  `fetch` only throws on network failures. It does **not** throw on 401 or 404, so always check `response.ok` before reading the body.
</Callout>

<Callout type="info">
  `as WeatherData` tells TypeScript to trust the shape of the response. It is not a runtime check. That is acceptable here because the data comes from your own route.
</Callout>

### The same call with axios

If you prefer `axios` (`npm install axios`), `axios` throws automatically for 4xx and 5xx statuses:

```ts filename="lib/weather.axios.ts"
import axios, { AxiosError } from 'axios'
import { WeatherApiError, messageForStatus } from '@/lib/weather'
import type { WeatherData } from '@/lib/types'

export async function fetchWeatherWithAxios(city: string): Promise<WeatherData> {
  try {
    const { data } = await axios.get<WeatherData>('/api/weather', { params: { city } })
    return data
  } catch (error) {
    if (error instanceof AxiosError && error.response) {
      throw new WeatherApiError(messageForStatus(error.response.status), error.response.status)
    }
    throw new WeatherApiError('Network error. Please check your internet connection.', 0)
  }
}
```

## 4. Save recent searches

We store the last five cities in the browser with `localStorage`.

```ts filename="lib/history.ts"
const KEY = 'recent-cities'
const MAX_ENTRIES = 5

export function loadHistory(): string[] {
  if (typeof window === 'undefined') return []

  try {
    const raw = window.localStorage.getItem(KEY)
    return raw ? (JSON.parse(raw) as string[]) : []
  } catch {
    return []
  }
}

export function addCity(city: string): string[] {
  const updated = [
    city,
    ...loadHistory().filter((item) => item.toLowerCase() !== city.toLowerCase()),
  ].slice(0, MAX_ENTRIES)

  try {
    window.localStorage.setItem(KEY, JSON.stringify(updated))
  } catch {
    // Storage can be full or blocked. The dashboard still works without history.
  }

  return updated
}
```

`addCity` removes an older copy of the same city first, so a city never appears twice, and the newest search is always first.

<Callout type="info">
  `localStorage` does not exist on the server, which is why `loadHistory` checks `typeof window`. We also read it inside `useEffect` in the next step, so the server and the browser render the same HTML first.
</Callout>

## 5. Build the dashboard page

The page is a small state machine driven by `status`: idle, loading, error and success.

```tsx filename="app/page.tsx"
'use client'

import { useEffect, useState } from 'react'
import RecentSearches from '@/components/RecentSearches'
import SearchBar from '@/components/SearchBar'
import WeatherCard from '@/components/WeatherCard'
import { addCity, loadHistory } from '@/lib/history'
import type { SearchStatus, WeatherData } from '@/lib/types'
import { fetchWeather, WeatherApiError } from '@/lib/weather'

export default function Home() {
  const [status, setStatus] = useState<SearchStatus>('idle')
  const [weather, setWeather] = useState<WeatherData | null>(null)
  const [errorMessage, setErrorMessage] = useState('')
  const [history, setHistory] = useState<string[]>([])

  useEffect(() => {
    setHistory(loadHistory())
  }, [])

  async function search(city: string) {
    setStatus('loading')
    setErrorMessage('')

    try {
      const data = await fetchWeather(city)
      setWeather(data)
      setHistory(addCity(data.name))
      setStatus('success')
    } catch (error) {
      setErrorMessage(
        error instanceof WeatherApiError
          ? error.message
          : 'Something went wrong. Please try again.',
      )
      setStatus('error')
    }
  }

  return (
    <div>
      <h1 className="mb-6 text-2xl font-bold">Weather Dashboard</h1>

      <SearchBar onSearch={search} disabled={status === 'loading'} />
      <RecentSearches cities={history} onSelect={search} />

      <div className="mt-6">
        {status === 'idle' && (
          <p className="text-slate-600">Search for a city to see its weather.</p>
        )}

        {status === 'loading' && (
          <p role="status" className="text-slate-600">
            Loading weather...
          </p>
        )}

        {status === 'error' && (
          <div role="alert" className="rounded-xl border border-red-200 bg-red-50 p-4 text-red-800">
            {errorMessage}
          </div>
        )}

        {status === 'success' && weather && <WeatherCard data={weather} />}
      </div>
    </div>
  )
}
```

### How the pieces work together

<Steps>

### The user searches

`SearchBar` calls `search(city)`. The page sets `status` to `loading`, which also disables the button so the user cannot send the request twice.

### The request finishes

On success we store the weather, add the API's own spelling of the city to the history, and move to `success`. On failure the `catch` block saves a readable message and moves to `error`.

### The user picks a recent city

Clicking a recent search calls the same `search` function, so there is only one code path to maintain.

</Steps>

<Callout type="warning">
  Always keep the **loading** and **error** states. Without them, a slow network shows nothing, and a failed request leaves the user with no explanation.
</Callout>
