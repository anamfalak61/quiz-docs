# UI & Styling

In this guide we build the look of the Weather Dashboard: a responsive layout, a search bar, a weather card with **dynamic weather icons**, and a recent searches list, all with **Tailwind CSS**.

<Callout type="info">
  Complete the [Setup guide](/setup/folder-structure) first. This guide only builds the interface. The data fetching comes in the [Implementation guide](/guides/implementation).
</Callout>

## 1. Page layout

Content is centered, full width on mobile, and limited by `max-w` on large screens.

```tsx filename="app/layout.tsx"
import type { ReactNode } from 'react'
import './globals.css'

export const metadata = {
  title: 'Weather Dashboard',
  description: 'Search the weather in any city',
}

export default function RootLayout({ children }: { children: ReactNode }) {
  return (
    <html lang="en">
      <body className="min-h-screen bg-slate-100 text-slate-900">
        <main className="mx-auto w-full max-w-md px-4 py-8 sm:py-12">
          {children}
        </main>
      </body>
    </html>
  )
}
```

| Class | Purpose |
| --- | --- |
| `min-h-screen` | Page is at least as tall as the screen |
| `max-w-md` | Limits content width on large screens |
| `mx-auto` | Centers the content |
| `px-4 py-8 sm:py-12` | Small spacing on mobile, larger on bigger screens |

## 2. Search bar

A text input and a button. The component only collects the city name and calls `onSearch`. It does not know anything about the API.

```tsx filename="components/SearchBar.tsx"
'use client'

import { useState, type FormEvent } from 'react'

interface SearchBarProps {
  onSearch: (city: string) => void
  disabled?: boolean
}

export default function SearchBar({ onSearch, disabled = false }: SearchBarProps) {
  const [value, setValue] = useState('')

  function handleSubmit(event: FormEvent<HTMLFormElement>) {
    event.preventDefault()
    const city = value.trim()
    if (city) onSearch(city)
  }

  return (
    <form onSubmit={handleSubmit} className="flex gap-2">
      <label htmlFor="city" className="sr-only">
        City name
      </label>
      <input
        id="city"
        type="text"
        value={value}
        onChange={(event) => setValue(event.target.value)}
        placeholder="Search a city, e.g. Lahore"
        className="min-w-0 flex-1 rounded-lg border border-slate-300 bg-white px-4 py-2.5 outline-none focus:border-violet-500"
      />
      <button
        type="submit"
        disabled={disabled}
        className="rounded-lg bg-violet-600 px-5 py-2.5 font-medium text-white hover:bg-violet-700 disabled:opacity-50"
      >
        Search
      </button>
    </form>
  )
}
```

<Callout type="info">
  The hidden `label` (class `sr-only`) is for screen readers. It costs nothing and makes the input accessible.
</Callout>

## 3. Dynamic weather icons

The API returns an icon code for each condition, for example `10d` for rain during the day. The image for that code is available at:

```text
https://openweathermap.org/img/wn/10d@2x.png
```

The last letter of the code tells you the time of day: `d` for day and `n` for night. The weather data you typed in `lib/types.ts` already contains this code in `weather[0].icon`.

### Allow the image domain

`next/image` only loads images from domains you approve. Add the icon host to `next.config.ts`:

```ts filename="next.config.ts"
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  images: {
    remotePatterns: [
      {
        protocol: 'https',
        hostname: 'openweathermap.org',
        pathname: '/img/wn/**',
      },
    ],
  },
}

export default nextConfig
```

<Callout type="warning">
  Restart the dev server after editing `next.config.ts`. The new setting is not picked up while the server is running.
</Callout>

## 4. Weather card

The card shows the city, temperature, icon and description. Its background color depends on the condition, so the card itself changes with the weather.

```tsx filename="components/WeatherCard.tsx"
import Image from 'next/image'
import type { WeatherData } from '@/lib/types'

function backgroundFor(main: string, icon: string): string {
  const isNight = icon.endsWith('n')

  switch (main) {
    case 'Clear':
      return isNight ? 'bg-indigo-900' : 'bg-sky-500'
    case 'Clouds':
      return 'bg-slate-500'
    case 'Rain':
    case 'Drizzle':
      return 'bg-blue-800'
    case 'Thunderstorm':
      return 'bg-purple-900'
    case 'Snow':
      return 'bg-sky-300'
    default:
      return 'bg-slate-400'
  }
}

export default function WeatherCard({ data }: { data: WeatherData }) {
  const condition = data.weather[0]
  if (!condition) return null

  return (
    <section
      className={`rounded-2xl p-6 text-white shadow-md ${backgroundFor(condition.main, condition.icon)}`}
    >
      <p className="text-sm opacity-90">
        {data.name}, {data.sys.country}
      </p>

      <div className="flex items-center justify-between">
        <p className="text-6xl font-bold">{Math.round(data.main.temp)}°C</p>
        <Image
          src={`https://openweathermap.org/img/wn/${condition.icon}@2x.png`}
          alt={condition.description}
          width={100}
          height={100}
        />
      </div>

      <p className="capitalize">{condition.description}</p>

      <dl className="mt-5 grid grid-cols-3 gap-3 text-center text-sm">
        <div className="rounded-lg bg-white/20 p-3">
          <dt className="opacity-80">Feels like</dt>
          <dd className="font-semibold">{Math.round(data.main.feels_like)}°C</dd>
        </div>
        <div className="rounded-lg bg-white/20 p-3">
          <dt className="opacity-80">Humidity</dt>
          <dd className="font-semibold">{data.main.humidity}%</dd>
        </div>
        <div className="rounded-lg bg-white/20 p-3">
          <dt className="opacity-80">Wind</dt>
          <dd className="font-semibold">{data.wind.speed} m/s</dd>
        </div>
      </dl>
    </section>
  )
}
```

A few things worth noticing:

- `data.weather[0]` can be `undefined` in strict mode (`noUncheckedIndexedAccess`), so we check it before using it. This is the reason that option was turned on in the setup guide.
- `main` is the broad condition group, such as `Clear`, `Clouds`, `Rain` or `Snow`. Mist, haze, fog and similar conditions fall into the `default` case.
- The icon image gives the exact condition. The background color gives the overall mood.

<Callout type="warning">
  Tailwind cannot detect dynamic class names such as `` `bg-${color}-500` ``. Always write the full class name, like `bg-sky-500` above.
</Callout>

## 5. Recent searches list

This component only displays the list and reports a click. Saving the list comes in the Implementation guide.

```tsx filename="components/RecentSearches.tsx"
interface RecentSearchesProps {
  cities: string[]
  onSelect: (city: string) => void
}

export default function RecentSearches({ cities, onSelect }: RecentSearchesProps) {
  if (cities.length === 0) return null

  return (
    <section className="mt-6">
      <h2 className="mb-2 text-sm font-semibold text-slate-600">Recent searches</h2>
      <ul className="flex flex-wrap gap-2">
        {cities.map((city) => (
          <li key={city}>
            <button
              type="button"
              onClick={() => onSelect(city)}
              className="rounded-full border border-slate-300 bg-white px-3 py-1 text-sm hover:border-violet-400"
            >
              {city}
            </button>
          </li>
        ))}
      </ul>
    </section>
  )
}
```

## 6. Check responsiveness

Open browser DevTools (**F12**), toggle the device toolbar, and test these sizes:

<Steps>

### Mobile (375px)

The search bar and card use the full width. The three small boxes (feels like, humidity, wind) stay in one row.

### Tablet (768px)

The content stays centered at `max-w-md` with extra space on both sides.

### Desktop (1280px)

Same centered column. A narrow column is deliberate, because a weather card reads best at this width.

</Steps>
